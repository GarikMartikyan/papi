# papi

Базовый проект админ-панелей: ядро в `lib/`, панель в `src/`. Панели — клоны этого
репозитория, ядро приезжает к ним через `git merge upstream/main`.

## Язык ответов

Отвечай пользователю **по-русски**.

Это правило только про ответы в чате. Стиль кода оно не меняет: комментарии, названия и
тексты в самих файлах пишутся так же, как в существующих, — новый язык туда не переносится.

## `lib/` — read-only в панелях

Проверь ремоуты, прежде чем править ядро:

- Ремоут `upstream` есть — это панель. **`lib/` не трогаем.** Правка там станет конфликтом
  при первом же обновлении ядра. Нужное изменение вносится в репозиторий papi. Пока его нет,
  решение ищется на стороне панели: почти всё в ядре настраивается пропсами и конфигом.
- Ремоута `upstream` нет — это сам papi. Ядро здесь и правится.

`.githooks/pre-commit` отклонит коммит с изменениями под `lib/` в панели. Обходить его через
`PAPI_ALLOW_LIB=1` без явной просьбы пользователя нельзя.

## Границы импортов

- Панель видит ядро только через барели: `@papi/components`, `@papi/hooks`, `@papi/store`.
  Глубокие пути (`@papi/components/MainLayout/MainLayout`) запрещены — eslint ругается.
- Внутри `lib/` импорты относительные. Алиас `@papi/*` там не используется.
- Ядро не зависит от панели: импортировать что-либо из `src/` в `lib/` нельзя ни при каких
  обстоятельствах.

Новая публичная сущность ядра добавляется в барель своей папки (`lib/<папка>/index.ts`) —
больше нигде её регистрировать не нужно, алиас и резолв работают на папку целиком.

## Соглашения по коду

Живут в `.claude/skills/`: `component-pattern`, `hook-pattern`, `temp-code-todo`. Они в силе
и для `lib/`, и для `src/`.

## Проверка работы

```bash
npm run typecheck && npm run lint && npm run build
```

Сборки у ядра нет — `lib/` компилируется вместе с `src/`, поэтому отдельного шага для правки
ядра не существует, и dev-сервер подхватывает её сразу.
