# temp-code-todo — помечать временный код через TODO

papi пишется раньше панелей, которые его используют, поэтому здесь много кода-заглушек. Каждый
такой кусок обязан нести `TODO` **сверху** — иначе временное решение незаметно уезжает в релиз и
выглядит как обдуманное.

## Правило

Комментарий ставится **над** кодом: над константой, функцией, полем интерфейса или первой строкой
блока.

```
// TODO: <что это за заглушка> — <чем её заменить>
```

Обязательны обе части. `// TODO: fix` бесполезен: через месяц непонятно ни что не так, ни каким
должен быть правильный вариант. Если замена зависит от внешнего условия — назвать его прямо
(«когда будет известен формат», «когда появится эндпоинт», «после подключения i18n»).

Тикетов в papi нет — пишем просто `// TODO:`.

## Что считается временным

- Провизорные регулярки, enum'ы и списки допустимых значений, заданные «на глазок»
- Пустые барели `export {}` и точки входа без кода
- Захардкоженные значения, которые позже придут из API, конфига панели или сессии
- Стабы, no-op обработчики, фиктивные задержки и промисы
- Mock/fake/sample данные и фикстуры
- Любое место, которое вы описали бы словами «пока так», «временно», «до тех пор пока»

## Примеры из репозитория

```ts
/**
 * TODO: заменить на реальный формат projectId, когда он будет известен
 * (например `/^\d+$/`). Сейчас шаблон намеренно широкий — пропускает и числа,
 * и слаги, но отсекает пути, кавычки, пробелы и слишком длинные значения.
 */
const PROJECT_ID_PATTERN = /^[A-Za-z0-9_-]{1,64}$/;
```

```ts
// TODO: заглушка — пустой барель. Наполнится, когда здесь появится код.
export {};
```

Для JSX — комментарий-нода над заглушкой: `{/* TODO: … */}`.

## Не помечать

- Готовый код и осознанные постоянные дефолты — TODO не нужен
- Голый `// TODO` без объяснения или спрятанный в середине блока вместо верха

## При правке чужого TODO

Меняете код, который закрывает TODO, — удалите комментарий. Оставленный устаревший TODO хуже
отсутствующего: он врёт о состоянии кода.
